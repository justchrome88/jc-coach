# Правила работы Codex-агента в этом репозитории

## Главный принцип

Не делать “большую платформу”. Делать рабочий личный инструмент, который можно запустить и использовать.

## Перед началом работы

1. Изучи все `.md` файлы в корне репозитория.
2. Кратко сформулируй план работ.
3. Проверь текущую структуру проекта.
4. Не начинай переписывать всё без причины.

## Во время работы

1. Делай изменения маленькими законченными шагами.
2. После каждого крупного шага запускай тесты или хотя бы smoke-check.
3. Не ломай уже рабочий функционал.
4. Не добавляй зависимости без необходимости.
5. Не добавляй сложный frontend, если задача не требует.
6. Не коммить `.env`, ключи, токены, демки пользователя.
7. Все пути, настройки и ключи — через `.env` или config.
8. Пиши README по фактическому состоянию проекта.

## Приоритеты

Приоритет 1:
- импорт данных;
- хранение матчей;
- аналитика;
- coach report;
- запуск на VPS.

Приоритет 2:
- приятный dashboard;
- графики;
- тесты;
- документация.

Приоритет 3:
- demo parsing;
- Steam auth;
- расширенная архитектура.

## Запреты

Не делать в MVP:

- платежи;
- публичную регистрацию;
- сложные роли;
- Kubernetes;
- микросервисы;
- React/Next.js без отдельного указания;
- автоматический Steam match import без изучения ограничений;
- обход защит Steam/Valve/Faceit/любых сайтов.

## Качество кода

Требования:

- понятные имена функций;
- разделение слоёв: routes, services, models, templates;
- тесты на ключевую бизнес-логику;
- обработка ошибок импорта;
- не падать на неполных данных;
- не плодить дубли матчей;
- логировать важные действия.

## Формат финального ответа Codex

После работы вывести:

1. Что сделано.
2. Какие команды запускать.
3. Какие файлы изменены.
4. Как проверить результат.
5. Какие тесты прошли.
6. Что не успел.
7. Следующие задачи.
